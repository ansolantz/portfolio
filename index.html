Specialist area

Design Systems

A recurring part of my work has been turning design decisions into reusable systems. I’ve built and maintained Flutter component libraries, worked closely with designers in Figma and helped keep design and code aligned as products evolve.

01

Design + code as one system

I work closely with designers from the start, turning Figma components and specifications into reusable Flutter components. I care about keeping naming, structure and behaviour consistent between design and code.

02

Reusable Flutter libraries

I’ve built and maintained Flutter Design System libraries covering foundations, themes and reusable components. The goal is to make components easy for product developers to understand, reuse and extend.

03

Reference app + documentation

I use example and reference apps to make components easy to explore in their different states and variants. Clear documentation helps product teams use the system without having to know how it was built.

04

Accessibility + quality

Accessibility is considered when components are designed and implemented, not added as a separate step later. I’ve also used golden tests to catch visual regressions and treated states, theming and platform behaviour as part of the component itself.

How I work

From Figma specification to tested component.

Design tokens connect visual decisions to implementation. Components are then built, documented and demonstrated in the reference app, with automated visual tests helping catch regressions before changes reach products.

Figma→Tokens→Flutter API→Reference app→Golden tests
One source of truth

Shared foundations and components reduce duplicated UI decisions and keep experiences consistent across products.

Faster product work

Teams can focus on feature-specific problems instead of repeatedly rebuilding and styling common UI.

Safer change

Centralised tokens, components and tests make system-wide changes easier to propagate and visual regressions easier to catch.

Case study 01

LiveWell by Zurich

Building a Design System from the ground up while contributing to a health and wellbeing product.

RoleSenior Flutter Developer
FocusDesign Systems, product development
PlatformFlutter, mobile and web
01 Context 02 My work 03 The system 04 Outcome
01

Creating a shared foundation

I built and evolved the LiveWell Design System from the ground up, working closely with design and product to establish a shared visual and technical foundation. The system had to work in real product flows, not just as an isolated component library.

02

From foundations to product

Foundations

Defined color, typography, spacing, sizing, radius, icons and dark mode as reusable foundations.

Components

Built reusable Flutter components and tokens with well-structured APIs, clear conventions and maintainability in mind.

Accessibility

Incorporated accessibility into components and design standards instead of treating it as a later layer.

Adoption

Worked with product teams to replace legacy components and gradually move the app towards the new system.

Product work

Contributed directly to product features, including health and activity tracking, while also working through UX issues and technical debt.

Design System = design + code

A system for how products look, behave and scale.

The Design System brought together foundations, components, patterns, guidelines, code and governance. For designers it created a shared set of rules and decisions. For developers it created reusable code, theming and cross-platform consistency.

Product work

From shared components to a working product experience.

Alongside the Design System, I contributed to product features including health and activity tracking. Working on both sides helped keep the components grounded in real user flows rather than designing the library in isolation.

04 · Outcome

A more consistent, accessible and scalable product experience.

The Design System made it easier for teams to build and maintain new features while moving the product toward higher reuse and consistency. The next step was to think beyond a single application and explore how the same foundations could support a wider ecosystem.

01

From product to ecosystem

After LiveWell, I worked on the next step of the Design System approach within Zurich Global Ventures. The goal was to create a shared foundation that could be reused across multiple apps while still allowing each product to keep its own identity.

The focus shifted from consistency within one app to exploring how a shared system could support multiple products and teams without flattening their individual identities.

01

Share what should be shared

Core building blocks and conventions reduce repeated effort across teams.

02

Keep products flexible

A shared system should enable product identity, not flatten every experience into the same UI.

03

Build for maintenance

Improvements to shared foundations can benefit multiple apps instead of being solved repeatedly.

Case study 04

Natural Machines

Designing and building the user experience for Foodini, a 3D food printer with its interface running directly on an integrated Android tablet.

RoleJavaScript / Flutter Developer
ProductFoodini 3D food printer
TechnologyReact, JavaScript, Flutter

01

A very different kind of product interface

Foodini is a 3D food printer, which meant designing for an experience very different from a conventional mobile or desktop application. The interface had to make an unfamiliar physical process feel understandable and approachable on the machine's integrated touchscreen.

I worked initially with React and JavaScript, then helped build the next generation UI in Flutter as the product moved to a new cross-platform codebase.

01

Physical + digital

The UI was part of a real appliance, connecting software interactions with a physical printing process.

02

Make the unfamiliar clear

The experience needed to guide users through a new way of preparing food without making the technology feel complicated.

03

React to Flutter

The product gave me early hands-on experience moving an existing interface from React and JavaScript to Flutter.
